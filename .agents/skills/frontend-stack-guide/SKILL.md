This skill is the **Master Frontend Router & Complete Lifecycle Operating System** for the entire agentic environment. It integrates **ALL UI/UX, Design, Motion, Component, Architecture, and Quality skills** into one unified, non-redundant execution engine.

## 2. Il Flusso Operativo in 6 Fasi (The 6-Phase Lifecycle)

```
┌────────────────────────────────────────────────────────────────────────┐
│                   FRONTEND MASTERY OPERATING SYSTEM                    │
├────────────────────────────────────────────────────────────────────────┤
│ 1. DISCOVERY & POSTURE      │ taste-skill + ui-ux-pro-max + blueprint  │
│ 2. SUBAGENT ORCHESTRATION   │ agent-creator (Frontend Specialist)      │
│ 3. ROADMAP & MILESTONES     │ master-project-planner (UI Component DoD)│
│ 4. 4-LAYER CRAFT PIPELINE   │ shadcn + 21st + uiverse + gsap           │
│ 5. POLISH & CRITIQUE        │ impeccable (Spacing, Copy, Hierarchy)    │
│ 6. ANTI-BIAS AUDIT GATE     │ the-judge + mock-hunter + a11y + lcp     │
└────────────────────────────────────────────────────────────────────────┘
```

### Fase 1: Discovery & Postura Estetica (Zero AI-Slop)
1. **Calibrazione Dials (`taste-skill`)**:
   - `DESIGN_VARIANCE` (1-10): Asimmetria e carattere.
   - `MOTION_INTENSITY` (1-10): Reattività micro-interazioni e scroll.
   - `VISUAL_DENSITY` (1-10): Densità informativa vs whitespace.
2. **Sistema di Design & Tipografia (`ui-ux-pro-max` + `frontend-design`)**:
   - Palette coerente (niente gradienti viola generici).
   - Coppia tipografica curata (es. `Geist Sans` + `Instrument Serif`).
   - Spacing scale matematico (4px/8px grid).

### Fase 2: Generazione Subagente Dedicato (`agent-creator`)
Se il progetto richiede sviluppo UI continuativo:
- Genera il subagente specialista (es. `[project]-ui-specialist`) con `enable_write_tools: true`.
- Iscrivi il subagente in `AGENTS.md` sotto `## Subagents & Roles`.

### Fase 3: Pianificazione & Definition of Done (`master-project-planner`)
Ogni task frontend inserito in `MASTER_PLAN.md` deve soddisfare la **UI Component Definition of Done (DoD)**:
- [ ] **Loading State**: Skeletons o spinner dedicato (`uiverse`).
- [ ] **Empty State**: Messaggio chiaro e CTA quando non ci sono dati.
- [ ] **Error State**: Fallback visivo chiaro se la query fallisce.
- [ ] **Keyboard Accessible**: `:focus-visible` chiaro e navigazione logica da tastiera.
- [ ] **Mobile Safe Area**: Rispetto di safe area iOS/Android su schermi piccoli.

### Fase 4: La Catena di Montaggio a 4 Livelli (Craft Pipeline)
1. **Layer 0 (Tokens)**: `tailwind-patterns` (CSS variables semantiche).
2. **Layer 1 (Primitives)**: `shadcn` (dialoghi, form, dropdown, bottoni accessibili).
3. **Layer 2 (Bento & Hero Blocks)**: `21st` MCP (bento grid, card luminose, sezioni hero).
4. **Layer 3 (Micro-UI & Flair)**: `uiverse` (interruttori toggle personalizzati, loader futuristici, CTA magnetiche).
5. **Layer 4 (Motion)**: `gsap-animation` (`useGSAP`, timeline, ScrollTrigger).
6. **Layer 5 (Architecture)**: `react-composition-patterns` (compound components).

### Fase 5: Polish Visivo & Design Critique (`impeccable`)
Prima di considerare l'interfaccia pronta:
- Attiva **`impeccable`** per:
  - Verificare che il layout non sia "troppo rumoroso o troppo sciatto".
  - Correggere la gerarchia visiva (pesi dei titoli, contrasti secondari).
  - Revisionare il micro-copy (messaggi di errore amichevoli, etichette coerenti).
  - Assicurare consistenza tra padding interni delle card e margini esterni.

### Fase 6: Quality Gate Anti-Bias & Anti-Allucinazione
1. **Separazione Autore vs Revisore**: L'agente che scrive la UI non può auto-approvarsi nello stesso thread. La verifica deve passare per un subagente QA isolato o per **`the-judge`**.
2. **Audit delle Prove Empiriche**:
   - `lint-and-validate` / `tsc --noEmit`: 0 errori verificati a terminale.
   - `mock-hunter`: Zero mock data non censiti lasciati nel codice.
   - `a11y-debugging`: Contrasto WCAG AA e zero keyboard trap.
   - `debug-optimize-lcp` + `react-best-practices`: Core Web Vitals sotto budget, immagini con `priority`/`lazy`.

## 3. Protocollo di Conscious Debugging (Quando l'utente segnala un errore)

Se l'utente segnala un bug visivo o layout glitch:
1. **Vietato dire "Ho corretto" senza prove**: non applicare patch a caso (es. `!important` o `z-index: 9999`).
2. **Ciclo di Risoluzione Cosciente**:
   - **Locate**: Individua il file e le classi computate responsabili (`file:line`).
   - **Diagnose**: Isola la root cause (z-index collassato, flexbox overflow, listener non rimosso).
   - **Surgical Patch**: Applica la minima modifica necessaria senza rompere gli altri breakpoint.
   - **Proof**: Mostra all'utente l'esatto motivo del problema e come il fix lo risolve matematicamente/visivamente.
